# NVIDIA NIM Provider コア安定化 設計書

**日付**: 2025-04-29
**スコープ**: VS Code 拡張機能 `nvidia-nim-provider` のコア機能安定化
**アプローチ**: A — コア機能の安定化（高インパクト・低コスト）

---

## 概要

GitHub Copilot Chat のネイティブモデルと同等のユーザー体験を提供するため、
以下の3領域に絞って既存コードの修正・拡張を行う。

---

## 1. Agent mode ツール呼び出し精度の向上

### 課題

- `tool-parser.ts` のテキスト埋め込みツール呼び出しパースが複雑でエッジケースに弱い
- リトライが 1 回のみで、リトライ時のシステムプロンプトが不十分
- モデルアダプターごとのツール呼び出しプロンプトに改善の余地あり

### 変更内容

| # | 変更 | 対象ファイル | 内容 |
|---|------|-------------|------|
| 1.1 | リトライ戦略の強化 | `provider.ts` (L800-901) | リトライ回数を `attempt < 2` → `attempt < 3`（最大2回）に。リトライ時プロンプトに「前回失敗した引数とエラー内容」を明示 |
| 1.2 | ツール引数修復の強化 | `tool-parser.ts` (`repairToolArguments`, L511-554) | 文字列→数値変換、ブール値正規化（`"true"`/`"false"`/`"yes"`/`"no"`/`1`/`0`）、必須フィールドの型ベースデフォルト値補完、ネストされた `arguments` フィールドの展開 |
| 1.3 | ツール呼び出しシステムプロンプトの見直し | `adapters/index.ts` (各アダプター) | DeepSeek系: `伏`/`ch` マーカー使用時のガイダンス強化。Kimi: 必須引数の明示的指示。Claude: JSON ブロック内出力の指示強化 |
| 1.4 | パース処理の中間ログ強化 | `tool-parser.ts` | 各パース段階（正規表現マッチ→JSONパース→修復）でのデバッグログ追加。パース失敗時の生テキストログ出力 |

### 期待効果

- Agent mode ツール呼び出し成功率の向上（特に DeepSeek 系モデル）
- パース失敗時のデバッグ容易性の向上

---

## 2. ストリーミング安定性の向上

### 課題

- `STREAM_IDLE_TIMEOUT_MS` が固定 120 秒で、長文生成時に途切れる
- ネットワーク切断時のリカバリーがない
- `<think>` タグフィルタがチャンク境界の不完全タグに対応していない

### 変更内容

| # | 変更 | 対象ファイル | 内容 |
|---|------|-------------|------|
| 2.1 | 動的アイドルタイムアウト | `api.ts` (`streamChatCompletion`) | モデルの `max_output_tokens` に応じてアイドルタイムアウトを計算: `min(300000, max(60000, max_output_tokens / 10 * 1000))` ms |
| 2.2 | クロスチャンク think タグ対応 | `utils.ts` (`filterThinkTagsFromChunk`) | 不完全な `<think>` 開始タグをバッファリングし、次のチャンク到着時に解決。`├` 文字（DeepSeek の思考終了マーカー）の検出強化 |
| 2.3 | エラーハンドリングの統一 | `api.ts`, `provider.ts` | `AbortError` の捕捉と、部分レスポンスの返却。ネットワークエラー発生時にユーザーへ「再試行」「ここまでで続行」の選択肢を提示 |
| 2.4 | Retry-After ヘッダー処理の堅牢化 | `api.ts` (`fetchWithRetry`) | `Retry-After` の値が「秒数」と「HTTP-date」の両形式に対応。パース失敗時はデフォルトのバックオフを使用 |

### 期待効果

- 長文生成・長時間ツール呼び出し中のタイムアウト減少
- `<think>` タグフィルタのチャンク境界バグ解消
- レート制限時のリカバリー速度向上

---

## 3. エラーUXの向上

### 課題

- エラーメッセージが英語かつ技術的
- API キー未設定時の導線が弱い
- デバッグログの有効化が手動（`NVIDIA_NIM_DEBUG=1`）

### 変更内容

| # | 変更 | 対象ファイル | 内容 |
|---|------|-------------|------|
| 3.1 | エラーメッセージの構造化 | `provider.ts`, `api.ts` | エラーパターンごとに `{ code, cause, action }` の構造化メッセージを定義。ユーザー表示用の日本語メッセージを追加 |
| 3.2 | APIキー未設定時の導線改善 | `provider.ts` (L385-393) | `showErrorMessage` に加えて `showInformationMessage` で「APIキーを設定」ボタン付き通知。クリックで `nvidia-nim.manage` コマンド実行 |
| 3.3 | 常時エラーログ出力 | `output-channel.ts` | `NVIDIA_NIM_DEBUG` の有無に関わらず、エラー（`appendLine` with `[ERROR]` prefix）と警告（`[WARN]`）は常に OutputChannel に出力 |
| 3.4 | ステータスバー表示 | `extension.ts`, 新規 `src/status-bar.ts` | VS Code ステータスバーにプロバイダー状態を表示: モデル数（通常時）/「接続中...」（リフレッシュ中）/「エラー」（失敗時）。クリックでモデルリフレッシュ |

### 期待効果

- トラブル発生時にユーザーが自力で解決できる可能性の向上
- サポート負荷の低減

---

## スコープ外

- MCP サーバー統合（`mcp-compat.ts` の本格実装）
- 設定UIの大幅リニューアル
- 新モデルの追加
- 既存テストの構造変更（新規テスト追加のみ）
- パフォーマンス計測基盤の新設

---

## 実装順序

1. **ステータスバー + エラーログ** (3.3, 3.4) — 最も小さく、後続の改善の品質確認に役立つ
2. **動的アイドルタイムアウト + Retry-After 堅牢化** (2.1, 2.4) — ストリーミングの根本的な安定性
3. **クロスチャンク think タグ対応** (2.2) + **エラーハンドリング統一** (2.3)
4. **リトライ戦略強化 + ツール引数修復** (1.1, 1.2) — Agent mode の中核改善
5. **ツール呼び出しプロンプト見直し** (1.3) — モデル別の微調整
6. **エラーメッセージ構造化 + APIキー導線** (3.1, 3.2) — UX 最終調整
